# ShopSphere — Customer Management Module

Management of customer data: personal information, order history and account settings. Administrators keep track of customers, add them, update their details and deactivate accounts when needed. Built for the ITVedant / Vibgyor Advisors integrated internship.

**Submission document:** [Anil_Nayak_ShopSphere - Customer Management Module Assignment Submission.pdf](Anil_Nayak_ShopSphere%20-%20Customer%20Management%20Module%20Assignment%20Submission.pdf). Its source is [Customer_Management_Module.html](Customer_Management_Module.html), and the screenshots are in [screenshots/](screenshots/).

## How to use it

1. Start MySQL, the backend (`Backend/ecommerce`: `mvnw.cmd spring-boot:run`) and the frontend (`Frontend/ecommerce`: `npm run dev`).
2. Open http://localhost:5173/login, choose the **Admin** tab and sign in (on a local setup, **Try a demo account → Admin**).
3. Click **Customers** in the left menu.

| Task | Steps |
|------|-------|
| Add a customer | **Add customer** → full name, email, mobile number, first password → **Add customer** |
| Find a customer | Search by name, email or phone; **All / Active / Inactive** |
| See order history | **View** in the row: personal information, saved addresses, orders with date, total and status |
| Update details | **Edit** → change name, email, phone or the Account status switch → **Save changes** |
| Deactivate (soft delete) | **Deactivate** → read the warning → **Deactivate** |
| Activate again | **Inactive** filter → **Activate** → **Activate** |

### Validation rules

| Field | Rule |
|-------|------|
| Full name | 2–100 characters; letters, spaces and `. ' -` (split into first and last name) |
| Email | Valid email, at most 100 characters, unique across all accounts (any capitalisation) |
| Mobile number | 10 digits starting with 6–9 |
| First password (add only) | 8–64 characters with an uppercase letter, a lowercase letter and a number; stored as a BCrypt hash |
| Status | Inactive customers are refused at sign-in: *"This account has been suspended. Please contact support."* |

Only accounts with role `CUSTOMER` are managed here. Seller and admin accounts give *"Customer … was not found."*; they are managed in **Sellers** and **Users**.

## Database design

Customers are rows of the `users` table with `role = 'CUSTOMER'`:

| Assignment column | Assignment type | ShopSphere column | Notes |
|-------------------|-----------------|-------------------|-------|
| `user_id` | int (pk, auto_increment) | `user_id` BIGINT PK AUTO_INCREMENT | |
| `first_name` | varchar(100) | `first_name` VARCHAR(100) | Generated by MySQL from `full_name` (first word) |
| `last_name` | varchar(100) | `last_name` VARCHAR(100) | Generated by MySQL from `full_name` (the rest) |
| `email` | varchar(100) | `email` VARCHAR(150) UNIQUE | Forms allow up to 100 characters |
| `phone` | varchar(15) | `phone` VARCHAR(15) | |
| `created_at` | datetime | `created_at` DATETIME(6) | |
| `updated_at` | datetime | `updated_at` DATETIME(6) | |
| `status` | boolean | `active` BIT(1) | 1 = active, 0 = inactive (soft delete) |

The generated columns are added once by `config/SchemaPatcher.java`:

```sql
ALTER TABLE users ADD COLUMN first_name VARCHAR(100)
  GENERATED ALWAYS AS (SUBSTRING_INDEX(TRIM(full_name), ' ', 1)) VIRTUAL;
ALTER TABLE users ADD COLUMN last_name VARCHAR(100)
  GENERATED ALWAYS AS (TRIM(SUBSTRING(TRIM(full_name),
                       CHAR_LENGTH(SUBSTRING_INDEX(TRIM(full_name), ' ', 1)) + 1))) VIRTUAL;
```

Order history comes from `orders.customer_id`, and saved addresses from `addresses.user_id`. SQL for every action (add, dashboard with order totals, search, order history, summary, update, deactivate, reactivate) is in [`DataBase/queries.sql`](../../DataBase/queries.sql), section 9. It was tested against the local database inside a transaction that was rolled back.

## API

All endpoints need an admin JWT (`Authorization: Bearer <token>`).

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/api/admin/customers?search=&active=&page=&size=` | Customer dashboard with order totals |
| GET | `/api/admin/customers/summary` | `{ total, active, inactive, newLast30Days, withOrders }` |
| GET | `/api/admin/customers/{id}` | `{ customer, addresses, recentOrders }` |
| POST | `/api/admin/customers` | Add `{ fullName, email, phone, password }` |
| PUT | `/api/admin/customers/{id}` | Update `{ fullName, email, phone, active }` |
| PATCH | `/api/admin/customers/{id}/status` | `{"active": false}` deactivate · `{"active": true}` activate |

Self-registration stays public: `POST /api/auth/register` then `POST /api/auth/verify-otp`.

Example: deactivate a customer with `curl` (replace `$TOKEN` and the ID):

```bash
curl -X PATCH http://localhost:8080/api/admin/customers/16/status \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"active":false}'
```
